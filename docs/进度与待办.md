## 二、✅ 已解决：`tick` 实测 **999.2/秒**（就是 1000/秒）

### 结论（2026-10-02 实测，用主机时钟做独立秒表）

直接读 `tick` 变量的内存地址 **`0x20000080`**（脚本 `tools\jlink_read_tick.jlink`）：

| 次 | 主机时钟时刻 | `tick` 值 |
|---|---|---|
| A | 06:28:13.661 | 22952 |
| B | 06:28:43.875 | 53143 |

Δ = 30191，Δt = 30.214 秒 → **999.2 /秒** ✅

**结论**：
- **芯片侧没问题** —— 1 ms 更新中断是准的，作业要求满足；
- **不准的是 Ozone 3.26 的 `Data Sampling` 时间列** —— 时间戳比真实时间短约 18%（1 kHz 与 100 Hz 两种采样率下偏差一致 → 是它的时间基准问题）；
- 因此 **附录图②改用 `Watched Data` 的两次读数**（两次读数之间用主机时钟计时），**不要**用 Data Sampling 的时间列来算速率。

### 已知事实

| 来源 | 内容 |
|---|---|
| Data Sampling **1 kHz** 采样 | 0.032674 s 内 `tick` 涨 27 → **826/秒** |
| Data Sampling **100 Hz** 采样 | 10 ms 一行、每行涨约 8.3 → **831/秒** |
| 代码 `Core\Src\main.c` 123–130 行 | HSE 开、PLL 源 = HSE、**PLLMUL ×9** → 8×9 = **72 MHz** |
| 代码 141–143 行 | AHB ÷1、**APB1 ÷2** → 定时器时钟 **72 MHz** |
| 代码 198–200 行 | **PSC = 71 / ARR = 999** → 72÷72÷1000 = **精确 1000 Hz** |

**代码说 1000，实测 831，差 17%。**

已排除的解释：~~"1 kHz 采样偷 CPU 时间"~~ —— 把采样率降到 100 Hz 后比例**没变**，所以不成立（该结论已收回）。

### 开机后按顺序做这三步

**第 1 步：秒表法实测（独立时钟，最硬的证据）**

| 步 | 动作 |
|---|---|
| 1 | Ozone 里 `Halt` → 记下 `tick` = **A** |
| 2 | `F5` 运行 |
| 3 | **同时开手机秒表**，等 **30 秒**整 |
| 4 | `Halt` → 记下 `tick` = **B** |
| 5 | 算 **(B − A) ÷ 30** = 真实每秒速率 |

**第 2 步：读芯片里的真实寄存器**

Ozone 的 **Memory 窗口**地址栏依次输入 → 截图：

| 地址 | 内容 |
|---|---|
| `40021000` | RCC_CR（HSE / PLL 起没起来） |
| `40021004` | RCC_CFGR（**关键**：实际 PLL 倍频、APB1 分频） |
| `40000028` | TIM2_PSC / TIM2_ARR |

**第 3 步：按结果分支处理**

| 秒表结果 | 结论 | 修法 |
|---|---|---|
| **≈ 1000/s** | 芯片没问题，是 **Ozone 的时间列不准** | 证据照交，说明里注明"已用秒表核对" |
| **≈ 830/s** | 定时器时钟实际约 **60 MHz**（晶振或倍频问题） | 把 `TIM2.Prescaler` 从 **71 改成 59**（60 MHz ÷ 60 ÷ 1000 = 1000 Hz）→ 重新编译烧录；或先查晶振是否真是 8 MHz |

## 五、踩过的坑（省下次的时间）

| 坑 | 现象 | 解法 |
|---|---|---|
| **USB 口挑食** | `Cannot connect to the probe/programmer` | 这只克隆 J-Link 只在部分 USB 口可用 → **换口**（认准能用的那个，别换来换去） |
| **开机后第一次连接失败** | 刚开机就连 → `FAILED`；等几秒再连 → `O.K.` | 开机后**等 ~10 秒**再连接（驱动/USB 还没就绪） |
| **两个程序抢 J-Link** | 烧录报 `Communication timed out` / `Failed to preserve target RAM` / `Target voltage too low (Measured: 0.0 Volt)`，Ozone 弹 `J-Link V7.00 Error` | **同一只 J-Link 同一时间只能被一个程序用** → 烧录前**完全退出 Ozone**（托盘里的 `JLinkGUIServer` 也要退） |
| **Data Sampling 时间列不准** | 按它的时间列算，`tick` 只有 831/秒 | 它的时间戳比真实时间短约 18% → 速率要用**主机时钟**或 `Watched Data` 两次读数来算 |
| Watched Data 运行时不刷新 | 运行时 `tick` 一直显示 0 | 它是"停下读一次"的机制 → 要么 `Halt`，要么用 **Data Sampling** |
| "找不到表格" | 表格被 **Memory 窗口**压在后面 | 点标签翻页；找不到隐藏窗口就用 **`Window`** 菜单 |
| 菜单里没有 `Target` | 找不到"下载并运行" | Ozone 3.26 里它叫 **`Debug`** |
| SVD 警告 | `STM32F103xx.svd has an unexpected byte size` | 只影响外设寄存器视图，**可忽略** |
| Ozone 装到一半消失 | `Ozone.exe` 不见了 | 重装安装包；**永远别跑 `Uninstall.exe`** |
| 烧录偶尔失败 | 写到一半报错 | 看门狗 2 秒超时（第 1 题不喂狗）→ **重跑一次脚本**即可 |
